# MDCP M3A0 Brief: Freeze the Schema-v12 Fixture

**Status:** Proposed and unopened. M2 acceptance, M1 owner approval, and
separate M3A0 test authorization are required before work.

## Objective and user-visible outcome

Create one immutable, genuine, checksummed schema-v12 database fixture that can
prove the later evidence-locator migration preserves representative evidence
and unrelated delivery state. This slice changes no production behavior.

## Controlling references

- `docs/design/managed-repository-documentation-contract.md`
- `docs/architecture/ADR-006-managed-repository-documentation-contract.md`
- `docs/architecture/ADR-007-proportional-delivery-validation.md`
- Accepted schema-v12 manifest in `ReleaseRadarCore/Store/StoreMigrations.swift`
- Existing schema-v10/v11 fixture conventions

## Scope

In scope:

- one schema-v12 SQLite fixture generated by accepted schema-v12 production
  code through a test-owned fixture-generation path;
- managed-eligible, arbitrary, missing, ticketless, and ticket-associated path
  evidence;
- unrelated phase, ticket, task, dependency, blocker, audit, review, goal,
  notification, receipt, and root/bookmark records sufficient for preservation
  assertions;
- exact manifest assertions and fixture-local SHA-256.

Out of scope:

- production source/schema changes, schema-v13, owner data, direct edits to
  fixture SQLite, application launch, migration, or evidence adoption.

## Dependencies and release gate

- M2 completed and accepted.
- Test execution separately owner-authorized.

## Anticipated files

  immutable manifest/semantic verification.
- Modify Xcode fixture membership only if required.

## Data, security, and privacy

Use synthetic repository roots and content only. The fixture must contain no
owner data, absolute owner path, credential, bookmark from a real repository,
or device identifier. Generate through store APIs/test setup, never manual
SQLite manipulation.

## Test-first strategy

RED is the missing exact fixture/attachment. GREEN verifies user version 12,
the accepted full manifest, deterministic representative semantic rows, no
schema-v13 columns, fixture checksum, and no production diff. A second run must
not silently replace the accepted fixture.

## Acceptance criteria

- Fixture is a genuine schema-v12 product of accepted code.
- All required legacy evidence classes and unrelated-state sentinels exist.
- Manifest and SHA-256 pass from the repository copy.
- No production, application state, held Issue #2 artifact, or existing fixture
  changes are included.

## Reviews and completion evidence

Required risk-triggered reviews: Code Review, QA, and Architecture. TPM
participates only if sequencing or dependencies materially change. Planning is
not an approval role. Delivery Management records concise fixture verification,
residual risks, and next eligible work; it is not an approval. Completion does
not authorize M3A.
