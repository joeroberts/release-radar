`baselineFromAssignmentID` chain. Require exact current project/root/common
repository, registration/generation, selected Codex context and full work identity
(ticket/task, phase/revisions, incarnation, outcome/title). Preserve all current

Successful intermediate candidates require closed connections. Recovered nodes
retain stopped status, confirmed connection closure, reserved launch, session,
uncertainty and valid recovery receipt. Match a recovered parent's direct child's
recorded baseline to the recovery candidate; revalidate the exact clean checkout.
The immediate closed successor supplies the new candidate. Reject missing,
cyclic, retired, stale or mismatched ancestry and dirty/replaced checkouts. Bound
traversal by the finite inventory with visited identities; no general Git ancestry
API is required. Exempt only qualifying recovered ancestors from delivery conflicts;
unrelated live/preparing/unknown/stopped/uncertain assignments and historical
registration conflicts still block. Recovered nodes remain invalid direct review
parents; normal review of a successful successor remains valid.

Recheck ancestry and conflict facts across configuration awaits and final admission
using existing serialization/CAS. STOP, policy/context changes, ancestry changes,
retirement and competing preparation must deny authorization. Preserve exact-request
replay and changed-body rejection. Audit finalization remains separate and must not
become a new continuation prerequisite.

No retirement changes, database edits, permissions/governance changes, public
commands, schema migration, generalized recovery framework or accepted ADR edits.
Preserve every existing branch, checkout, receipt, session and artifact.
