# RR-R10 Task 10 native verification

## Scope and direct checks

Non-authoritative verification evidence for the [Task 10 brief](../task-briefs/2026-08-29-delivery-goals-roadmap-readiness/task-10-phase-browsing-delivery-goals-brief.md).
The candidate was built on macOS 26.5.2 with Xcode, using the existing Debug
XCTest host entitlements, unique `com.rekonlabs.ReleaseRadar.Task10` identity,
inert LaunchServices startup and synthetic temporary stores. No installation,
live owner-goal acceptance, notification change or shared-service test occurred.

`xcodebuild build-for-testing` passed. Six focused AppRouteTests passed in
`model-final.xcresult`: per-project local browsing/reload without pointer or
audit writes; no-pointer browsing; explicit audited Make-active; trusted owner
acceptance and stale-inbox duplicate prevention; authorization and structural
revision failures; saved-but-refresh-failed recovery; and filtered-selection
reconciliation after a same-phase reload. The last regression first failed
with ROAD-1 still selected after reassignment, then passed after visible
membership changes triggered the existing reconciliation. Unchanged reloads
retain the ticket and its task count.

A second mounted-view regression reproduced an empty selection after changing
phases with a goal filter active. Refresh reconciliation is now restricted to
an unchanged byte-exact PhaseBoardKey so a phase switch can reset its filter
without clearing the new phase's selected ticket. Both mounted regressions
passed in `selection-final.xcresult` (2/2); the fresh Debug build also passed.
There are nine distinct passing Task 10 tests across the final model/native
runs, with the compact-only repeat validating the corrected native fixture.

Both named native tests passed: Phase Board at actual 1600 and 760-point content
widths (`planning-final.xcresult`), and Needs Review at 1100 points
(`needs-review-final.xcresult`). A focused compact-only rerun also passed
(`compact-keyboard-final.xcresult`) after giving each width a fresh NSWindow.
All bundles are retained under `.build/rr-r10-task10/runtime/`; they are
temporary diagnostics, not controlling artifacts. The canonical images below
are exported, visually inspected XCTest attachments from the inspected views.

## Keyboard and accessibility

Keyboard navigation was initially OFF. Under explicit coordinator delegation,
only System Settings → Keyboard → Keyboard navigation was temporarily enabled
for two bounded checks, then restored OFF after each; fresh AX readback
confirmed both restorations. Full Keyboard Access, VoiceOver and accessibility
permissions were not changed.

With Keyboard navigation ON, actual Tab/focus readback passed at both widths:
Viewed phase → Make active phase → plan summary → Delivery Goal → Show
unassigned → filter summary → density → cards. Space opened the explicit
Make-active confirmation; Escape cancelled and returned focus to its button.
Keyboard goal selection retained ROAD-1; Space on Show unassigned transferred
focus to the explanatory summary; the next Tab reached density. Task rows
remained read-only and were not added to the action traversal.

The first compact test reused a replaced host whose key-view loop did not
traverse controls. A fresh window per width resolved this test-fixture issue;
the compact-only repeat demonstrated the expected traversal without a product
focus workaround. Physical keyboard input, spoken VoiceOver output and native
macOS text-size settings were not exercised. The observed focus and accessible
explanation are direct evidence, not a claim about spoken announcements.
